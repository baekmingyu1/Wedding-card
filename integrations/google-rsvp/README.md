# 참석 여부 → Google Sheets 연결

청첩장 HTML은 정적으로 유지합니다. 저장은 Google Apps Script가 담당합니다.
Google Drive 연결만으로 Apps Script 웹 앱이 배포되는 것은 아닙니다.

## 최초 연결

1. 본인 Google Drive에서 비공개 구글 시트를 새로 만듭니다.
2. 시트에서 **확장 프로그램 → Apps Script**를 엽니다.
3. `Code.gs` 내용을 이 폴더의 `Code.gs`로 교체하고 저장합니다.
4. 함수 목록에서 `setupRsvp`를 선택해 실행하고 본인 계정에서 권한을 승인합니다.
   `참석 응답` 탭과 헤더가 만들어집니다. 시트 ID는 스크립트 속성에 저장됩니다.
5. **배포 → 새 배포 → 웹 앱**을 선택합니다.
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자** (하객 Google 로그인 불필요)
   - 조직 정책상 익명 웹 앱이 허용되지 않으면 해당 계정으로는 이 방식 사용 불가
6. 발급된 `https://script.google.com/macros/s/.../exec` 주소를
   `content.js`의 `rsvpEndpoint`에 넣습니다. `/dev` 주소는 사용하지 않습니다.
7. main에 반영한 뒤 실제 청첩장 주소와 카카오 브라우저에서 테스트 응답을 보냅니다.
   시트에 행이 생성되고 청첩장에서 완료 메시지를 받는 것까지 확인합니다.
   테스트 행은 확인 후 직접 삭제합니다.

## 저장 항목과 동작

접수 시간 / 구분 / 성함 / 참석 여부 / 본인 포함 인원 / 식사 여부 / 메시지 / 동의 / 접수 ID

- 불참은 인원 0명, 식사 `해당 없음`으로 저장합니다.
- 전송 중에는 중복 클릭을 막습니다. 같은 입력으로 재시도하면 접수 ID를 재사용합니다.
- Apps Script는 잠금과 접수 ID로 네트워크 재시도의 중복 행을 방지합니다.
- 페이지를 새로 열고 다시 작성한 답변은 별도 응답입니다. 개인 정보는 로컬 저장소에 보관하지 않습니다.
- 브라우저가 성공 JSON을 확인한 경우에만 완료로 표시합니다. 타임아웃·CORS·권한 오류 시 입력을 유지합니다.
- `no-cors`로 우회하여 저장되지 않은 응답을 성공으로 표시하지 않습니다.
- 응답 시트는 비공개를 유지합니다. 공개되는 것은 제출 URL이며 비밀번호나 토큰을 HTML에 넣지 않습니다.
- 이름/메시지 수식 실행 방지, 입력 검증, 간단한 봇 유도 필드를 포함합니다.
  공개 제출 URL 자체는 인증 수단이 아니므로 필요시 접수를 웹 앱 배포 중지로 종료하세요.
- 예식 이후 응답은 소유자가 필요에 따라 삭제합니다.

## 수정할 때

Apps Script 수정 후에는 **배포 관리 → 수정 → 새 버전**으로 배포해야 /exec에 적용됩니다.
청첩장 폼은 endpoint가 비어 있으면 제출이 비활성화됩니다.
실제 Google 계정의 승인과 웹 앱 배포 전에는 시트 저장·CORS·익명 접근 검증을 완료할 수 없습니다.
