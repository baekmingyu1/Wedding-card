# 모바일 청첩장

서버 없이 동작하는 정적 청첩장입니다. `index.html`을 브라우저에서 열어 미리 볼 수 있습니다.

## 내용과 사진 바꾸기

`content.js`에서 이름, 예식 정보, 첫 만남·PLAY·PAUSE 이야기, 초대글, 지도 링크, 계좌 정보를 수정합니다. 값이 확정되지 않은 버튼은 비활성화됩니다. 이야기 문구는 지금까지 들은 내용을 바탕으로 쓴 시안이므로 두 분의 말투에 맞게 다듬어 주세요.

오프닝은 `assets/opening/DSC*.jpg`의 파일명 순서대로 만든 **15장**을 사용합니다. 첫 사진이 준비되면 짧게 다음 장면을 버퍼링한 뒤 자동 재생합니다. 로딩 중에도 화면 아래의 **청첩장 바로 보기** 링크나 키보드의 본문 건너뛰기 링크로 바로 이동할 수 있습니다. 사진 요청은 최대 3개씩 진행하며, 건너뛰면 남은 오프닝 요청을 새로 시작하지 않습니다. 늦은 장면은 잠깐 기다린 뒤 이전 사진을 유지하며 넘어갑니다.

로딩 중에도 스크롤할 수 있습니다. 재생 중에는 일시정지하거나 건너뛸 수 있습니다. 모션 감소 설정을 켠 브라우저는 자동 재생 없이 한 화면의 사진을 보여줍니다. 깊은 링크나 스크롤 위치를 복원한 경우에는 기존 스크롤 방식으로 이동할 수 있습니다.

우측 목차의 `오프닝` 또는 맨 아래 `처음부터 다시 보기`를 누르면 첫 사진과 제목으로 돌아가 오프닝이 다시 시작됩니다. 본문에서 직접 맨 위로 스크롤해도 처음부터 재생됩니다.

모바일에서도 사진이 배경처럼 화면을 채우고 문구가 그 위에 나타납니다. 가로 사진의 전체 장면을 유지하기 위해 화면 주변은 같은 사진을 흐리게 확장하며, 모든 장면은 같은 위치에 고정됩니다.

원본 JPG는 `assets/opening/`에 보관하고 Git에서는 제외합니다. 웹용 사진은 480·768·1024·1600px WebP와 96px의 흐린 배경 이미지로 만들어집니다. 모바일은 최대 1024px 후보를 선택하며, PC는 화면 크기와 DPR에 맞게 최대 1600px 후보를 선택합니다. 각 파일명에 내용 해시가 들어가므로 사진을 다시 만들면 URL도 바뀝니다.

사진을 교체한 뒤에는 `npm install`과 `npm run images`를 실행하세요. 이 명령은 `opening-images.js`와 `index.html`의 첫 사진 preload를 함께 갱신합니다. `assets/opening/frames/`의 생성 파일과 변경된 HTML·JS를 한 번에 배포해야 합니다. 이전 파일은 캐시된 페이지를 위해 자동 삭제하지 않습니다. 이미지가 실패하면 자리 표시 화면을 사용하며 재생은 계속됩니다.

사진첩은 `assets/gallery/`에 사진을 넣고 `galleryPhotos`의 경로를 바꾸면 됩니다. 현재 빈 항목에는 오프닝 사진을 임시로 재사용합니다. 세로 사진을 권장하며, 웹에 맞게 크기와 용량을 줄여 주세요.

## 색감과 레이아웃

이 브랜치는 **PLAY / PAUSE** 컨셉입니다. 양식집에서의 첫 만남, 함께 즐기는 활동과 스포츠, 나란히 쉬는 시간을 이야기로 엮었습니다. `play-pause.css`에서 아이보리·짙은 녹색·주황색, 큰 타이포그래피와 이야기 카드의 모양을 조정할 수 있습니다. 기존 오프닝 사진 15장과 우측 목차를 유지합니다.

## 배포

운영에는 서버가 필요하지 않습니다. 배포 전 `npm run build`를 실행해 **`dist/`** 전체를 정적 호스팅에 올리세요. 빌드는 변경된 CSS·JS에 내용 해시가 들어간 파일명을 부여하고 원본 JPG를 제외합니다. `npm run images`는 사진을 바꿀 때만 개발 환경에서 실행합니다. 모든 경로는 상대 경로입니다.

## 확인할 화면

- 작은 모바일 화면에서 가로 스크롤이 없는지
- PC와 모바일에서 우측 목차 버튼으로 각 구역에 이동하는지
- 사진을 넣은 뒤 첫 사진이 표시되는지, 로딩 중 건너뛰기와 재생 중 일시정지가 동작하는지
- 지도와 복사 버튼이 확정된 정보에만 활성화되는지
