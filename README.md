# 모바일 청첩장

서버 없이 동작하는 정적 청첩장입니다. `index.html`을 브라우저에서 열어 미리 볼 수 있습니다.

## 내용과 사진 바꾸기

`content.js`에서 이름, 예식 정보, 첫 만남·PLAY·PAUSE 이야기, 초대글, 지도 링크, 계좌 정보를 수정합니다. 값이 확정되지 않은 버튼은 비활성화됩니다. 이야기 문구는 지금까지 들은 내용을 바탕으로 쓴 시안이므로 두 분의 말투에 맞게 다듬어 주세요.

오프닝은 `content.js`의 `openingPhotos`에 적힌 사진 수에 맞춰 동작합니다. 현재는 `DSC09569.jpg`부터 `DSC09583.jpg`까지의 **15장**을 파일명 순서대로 연결했습니다. 첫 사진을 보여준 뒤 나머지를 준비하고, 모두 준비되면 자동으로 순서대로 재생합니다. 사진이 끝나면 목차로 이동합니다. 사진이 없거나 불러오지 못하면 자리 표시 화면을 사용합니다.

사진을 준비하는 동안에는 오프닝에서 스크롤할 수 없습니다. 재생 중에는 일시정지하거나 건너뛸 수 있습니다. 모션 감소 설정을 켠 브라우저는 자동 재생 없이 한 화면의 사진을 보여줍니다. 깊은 링크나 스크롤 위치를 복원한 경우에는 기존 스크롤 방식으로 이동할 수 있습니다.

우측 목차의 `오프닝` 또는 맨 아래 `처음부터 다시 보기`를 누르면 첫 사진과 제목으로 돌아가 오프닝이 다시 시작됩니다. 본문에서 직접 맨 위로 스크롤해도 처음부터 재생됩니다.

모바일에서도 사진이 배경처럼 화면을 채우고 문구가 그 위에 나타납니다. 가로 사진의 전체 장면을 유지하기 위해 화면 주변은 같은 사진을 흐리게 확장하며, 모든 장면은 같은 위치에 고정됩니다.

원본 JPG는 `assets/opening/`에 보관하고 Git에서는 제외합니다. 웹용 사본은 `assets/opening/frames/01.webp`부터 `15.webp`까지이며, 공개되는 저장소에는 이 최적화된 사진이 포함됩니다. 사진을 추가하거나 순서를 바꾸면 웹용 사본과 `openingPhotos` 목록을 함께 수정하세요.

첫 사진을 우선 불러오고 나머지 사진을 이어서 준비합니다. 개별 사진이 실패하면 다시 시도하고 이전 장면으로 대체합니다. 사진을 다시 최적화해 같은 파일명으로 배포할 때는 `content.js`의 `?v=` 값을 올려 기존 브라우저 캐시를 갱신하세요.

사진첩은 `assets/gallery/`에 사진을 넣고 `galleryPhotos`의 경로를 바꾸면 됩니다. 현재 빈 항목에는 오프닝 사진을 임시로 재사용합니다. 세로 사진을 권장하며, 웹에 맞게 크기와 용량을 줄여 주세요.

## 색감과 레이아웃

이 브랜치는 **PLAY / PAUSE** 컨셉입니다. 양식집에서의 첫 만남, 함께 즐기는 활동과 스포츠, 나란히 쉬는 시간을 이야기로 엮었습니다. `play-pause.css`에서 아이보리·짙은 녹색·주황색, 큰 타이포그래피와 이야기 카드의 모양을 조정할 수 있습니다. 기존 오프닝 사진 15장과 우측 목차를 유지합니다.

## 배포

빌드와 서버가 필요하지 않습니다. `index.html`, `styles.css`, `play-pause.css`, `script.js`, `content.js`, `assets/`를 함께 정적 호스팅에 올리면 됩니다. CSS와 JavaScript는 상대 경로를 사용합니다.

## 확인할 화면

- 작은 모바일 화면에서 가로 스크롤이 없는지
- PC와 모바일에서 우측 목차 버튼으로 각 구역에 이동하는지
- 사진을 넣은 뒤 오프닝이 모두 준비되어 자동 재생되는지, 일시정지와 건너뛰기가 동작하는지
- 지도와 복사 버튼이 확정된 정보에만 활성화되는지
