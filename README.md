# 모바일 청첩장

서버 없이 동작하는 정적 청첩장입니다. `index.html`을 브라우저에서 열어 미리 볼 수 있습니다.

## 사진 인트로와 참석 응답

청첩장에 접속하면 사진 인트로부터 시작합니다. 지인 선택이나 이야기 화면 없이 사진 준비가 끝나면 자동 재생하며, 재생을 마치거나 건너뛰면 초대글로 이동합니다. 과거의 지인 선택 기록에 따라 인트로를 건너뛰지 않습니다. 사진 인트로는 로딩·일시정지를 제외하고 약 6~7초입니다.

오프닝 이미지는 최대 3개씩 불러오며, 본문으로 이동하면 대기 중인 추가 요청을 멈춥니다. 본문의 인트로 바로가기로 다시 볼 수 있고, 모션 감소 설정에서는 자동 재생을 생략합니다. `#rsvp` 등 본문 직접 링크와 복원된 스크롤 위치는 유지합니다.

본문의 참석 응답 폼은 기본 접힘 상태이며 ‘참석 여부 알려주기’를 누르면 펼치거나 접을 수 있습니다. 신랑측·신부측 구분은 폼에서 직접 선택합니다. 제출 후에는 현재 화면을 유지하고, 저장 실패 시 입력 내용을 유지하며 재시도할 수 있습니다. 이름과 참석 응답 내용은 브라우저 저장소에 저장하지 않습니다.

## 내용과 사진 바꾸기

`content.js`에서 이름, 부모님 성함, 예식 정보, 초대글, 참석 응답 링크, 교통 안내, 계좌 정보를 수정합니다. 신랑·신부 소개에는 전달받은 부모님 성함과 ‘아들·딸’ 관계를 표시합니다. 참석 응답 링크와 신부 측 계좌 정보는 아직 확정되지 않아 준비 문구로 표시하거나 링크를 숨깁니다.

본문은 **인트로 → 초대 멘트 → 캘린더 → D-DAY → 갤러리 → 참석 의사 전달 → 신랑 신부 소개 → 마음 전하실 곳 → Location → 오시는 방법 → 화환 사양 안내 → 청첩장 전달하기** 순서입니다. 별도 index 화면과 섹션별 제목·순서 표시는 없습니다. 신랑·신부 소개는 부모님 성함과 ‘아들/딸 이름’을 각각 두 줄로 표시합니다. 캘린더와 D-DAY는 `eventDate`를 기준으로 표시됩니다. 참석 응답은 `rsvpUrl`에 실제 응답 페이지의 HTTPS 주소를 넣으면 활성화됩니다. 네이버·카카오·구글 지도는 아르베 장소 공유·상세 링크로 연결됩니다. 지도 링크는 `naverMapUrl`, `kakaoMapUrl`, `googleMapUrl`에서 관리합니다. 버스 정류장명·노선·네이버 지도 검색 링크는 `busStops`에서 관리합니다. 정류장 번호는 표시하지 않으며, 정류장 이름 우측 `↗`로 지도 검색을 새 창에서 엽니다.

예식장 지도는 네이버 **Web Dynamic Map**으로 표시합니다. 지도에 가까워질 때 SDK를 불러오고, ‘눌러서 지도 움직이기’를 누르면 확대·이동할 수 있습니다. ‘예식장 위치로’는 원래 중심과 확대 수준으로 돌아가며, ‘지도 조작 마치기’ 또는 Escape로 다시 페이지를 편하게 스크롤할 수 있습니다.

네이버 클라우드 Maps Application에서 **Web Dynamic Map**을 활성화하고 실제 배포 주소 `https://welcome-our-wedding.cst.onul.me`를 **Web 서비스 URL**에 등록하세요. 공개 Key ID는 `content.js`의 `naverMapKeyId`, 기존 예식장 건물 좌표는 `naverMapCenter`에서 관리합니다. Secret Key는 공개 파일에 넣지 마세요. SDK 오류·인증 실패·12초 로딩 초과 시 기존 Static Map 이미지로 전환합니다(이 대체 이미지에도 **Static Map** 사용 권한 필요). 이미지도 실패하면 지도 바로가기 버튼으로 안내합니다. `file://`에서는 지도 인증을 사용할 수 없어 바로가기만 안내합니다. 실제 인증과 타일 표시는 등록된 배포 주소에서 별도로 확인해야 합니다.

달력 아래 **내 일정에 저장**은 캘린더 선택 팝업을 엽니다. Android의 ‘기기 캘린더’는 표준 `ACTION_INSERT` 인텐트로 일정 제목·장소·시작 시각을 전달하고, Google 선택은 Google 캘린더 패키지에 HTTPS 일정 작성 링크를 전달합니다. 사용자 클릭에서 직접 연결하며 새 탭이나 타이머로 앱을 실행하지 않습니다. 기기 캘린더가 해당 브라우저 연결을 지원하지 않으면 `browser_fallback_url`로 청첩장의 `#calendar-google` 경로에 돌아와 **Google 캘린더 앱으로 열기** 버튼을 표시합니다. 이 경로에서는 Google 웹으로 자동 이동하지 않습니다. 브라우저의 사용자 동작 제한 때문에 두 번째 앱은 버튼을 한 번 더 눌러 실행합니다. 같은 문서의 해시 이동과 페이지 재로딩을 모두 처리하고 경로는 `#calendar`로 정리합니다. Google 앱 자체를 열 수 없을 때만 기존 Google 웹 대체 경로를 사용합니다. 원래 선택창의 **앱 없이 웹으로 저장** 링크도 유지합니다. Android 이외 기기의 ‘기기 캘린더’는 `wedding.ics` 파일을 열고, Google 선택은 웹 작성 화면을 엽니다.

**제한:** 네이티브 앱의 INSERT 지원과 웹 브라우저에서의 실행 가능 여부는 다릅니다. 브라우저 실행에는 앱의 `BROWSABLE` 활동 지원이 필요하며, 웹사이트는 설치 앱 목록·앱 실행 성공·실제 일정 저장 여부를 확인하거나 보장할 수 없습니다. 삼성 캘린더가 이 연결을 지원하지 않으면 Google 앱 실행 버튼으로 안내합니다. 실제 삼성 기기에서 앱 실행과 일정 입력값을 별도 확인해야 합니다. 참고: [Android 일정 추가 인텐트](https://developer.android.com/guide/components/intents-common#Calendar), [브라우저 인텐트와 대체 URL](https://developer.chrome.com/docs/android/intents).

예식의 시작 시각만 전달하고, 미확정 종료 시각은 임의로 정하지 않습니다. Google 링크는 시작·종료에 동일한 시각을 전달하며 저장 전 종료 시각 확인 문구를 포함합니다. 저장한 일정은 청첩장 변경과 자동 동기화되지 않습니다.

`npm run calendar`는 `content.js`에서 루트의 `wedding.ics`를 갱신합니다. 예식 정보 변경 후 원본 폴더를 정적 서빙할 때 이 명령을 실행하고 HTML·JS와 일정 파일을 함께 반영하세요. `npm run build`도 같은 생성을 실행한 뒤 파일을 `dist/`로 복사하며, `npm run check:dist`는 원본·배포 파일과 현재 예식 정보의 일치를 검사합니다. 파일 내용이 같으면 생성 시각을 유지합니다. 방문 URL은 빌드 시 알 수 없으므로 일정 설명에 현재 페이지 주소를 넣지 않습니다.

호스팅은 `.ics`를 `Content-Type: text/calendar; charset=utf-8`로 제공해야 합니다. 강제 다운로드를 피하려면 `Content-Disposition: attachment`를 사용하지 않고, 필요하면 호스팅이 지원하는 방식으로 `inline; filename="wedding.ics"`를 설정하세요. `inline`도 캘린더 앱 실행을 보장하지 않습니다. 저장소에 특정 호스팅의 헤더 설정은 없으므로 실제 배포 응답과 사용할 모바일 브라우저에서 확인해야 합니다.

청첩장 전달하기는 기기의 공유 기능을 사용하고, 지원하지 않으면 주소를 복사합니다. 주소 복사 버튼은 언제든 사용할 수 있습니다. 화환 안내 문구는 `wreathMessage`에서 수정합니다.

오프닝은 `assets/opening/DSC*.jpg`의 파일명 순서대로 만든 **15장**을 사용합니다. 첫 방문에는 사진 15장을 준비하는 동안 진행률이 있는 로딩 화면을 보여 주고, 모두 화면 표시 준비를 마친 뒤 자동 재생합니다. 로딩 중에도 화면 아래의 **청첩장 바로 보기** 링크나 키보드의 본문 건너뛰기 링크로 바로 이동할 수 있습니다. 사진 요청은 최대 3개씩 진행하며, 건너뛰면 남은 오프닝 요청을 새로 시작하지 않습니다. 사진 전환 중에는 이전 장면을 유지하고 새 장면을 부드럽게 겹쳐 보여줍니다. 다음 사진은 미리 준비하고 표시 직전에 디코딩을 다시 확인하며, 지연되거나 실패하면 현재 사진을 유지합니다. 이전 장면은 고정 시간 후 숨기지 않고 새 장면이 완전히 불투명해진 뒤 정리합니다. 첫 사진은 1.5초, 중간 13장은 각각 0.2초, 마지막 사진은 2.4초 동안 보여주며 겹침 페이드는 0.1초입니다. 설정상 재생시간은 6.5초이며 로딩 화면 퇴장 0.55초와 디코딩 지연·일시정지 시간은 별도입니다.

로딩·자동 재생·일시정지 중에는 본문 스크롤과 포커스 이동을 잠급니다. 초대글 바로 보기나 키보드의 본문 건너뛰기로 즉시 잠금을 풀 수 있으며, 정상 재생 완료 시에도 본문으로 이동합니다. 재생 중에는 일시정지하거나 건너뛸 수 있습니다. 모션 감소 설정을 켠 브라우저는 자동 재생 없이 한 화면의 사진을 보여주고 스크롤을 잠그지 않습니다. 재생 중 모션 감소 설정을 켜도 잠금이 해제됩니다. 깊은 링크나 스크롤 위치를 복원한 경우에는 기존 스크롤 방식으로 이동할 수 있습니다.

우측 목차의 `오프닝` 또는 맨 아래 `처음부터 다시 보기`를 누르면 첫 사진과 제목으로 돌아가 오프닝이 다시 시작됩니다. 본문에서 직접 맨 위로 스크롤해도 처음부터 재생됩니다.

모바일과 세로 태블릿에서도 사진이 배경처럼 화면을 채우고 문구가 그 위에 나타납니다. 가로 사진의 전체 장면을 유지하기 위해 화면 주변은 같은 사진을 흐리게 확장하며, 모든 장면은 같은 위치에 고정됩니다.

원본 JPG는 `assets/opening/`에 보관하고 Git에서는 제외합니다. 웹용 사진은 480·768·1024·1600px WebP와 96px의 흐린 배경 이미지로 만들어집니다. 흐린 배경은 작은 데이터 이미지로 목록에 포함되어 사진 전환 전에 준비됩니다. 모바일은 최대 1024px 후보를 선택하며, PC는 화면 크기와 DPR에 맞게 최대 1600px 후보를 선택합니다. 각 파일명에 내용 해시가 들어가므로 사진을 다시 만들면 URL도 바뀝니다.

사진을 교체한 뒤에는 `npm install`과 `npm run images`를 실행하세요. 이 명령은 `opening-images.js`와 `index.html`의 첫 사진 preload를 함께 갱신합니다. `assets/opening/frames/`의 생성 파일과 변경된 HTML·JS를 한 번에 배포해야 합니다. 이전 파일은 캐시된 페이지를 위해 자동 삭제하지 않습니다. 이미지가 실패하면 자리 표시 화면을 사용하며 재생은 계속됩니다.

갤러리 원본 45장은 `assets/gallery/`에 보관합니다. `npm run gallery:images`를 실행하면 640·1200px WebP와 `gallery-images.js`가 만들어집니다. 원본 JPG는 Git·배포에서 제외하며, 한 페이지에 9장씩 보여줍니다. 사진을 추가·교체한 뒤 생성 명령을 다시 실행하세요. 사진 팝업에서는 핀치·더블 탭 확대를 제한하며, 본문에서는 브라우저 확대를 사용할 수 있습니다. 팝업을 연 뒤 브라우저 뒤로가기를 누르면 팝업부터 닫히며, 앞으로가기로 마지막으로 본 사진을 다시 열 수 있습니다. 닫기 버튼·팝업 바깥 여백·Escape로 닫아도 같은 히스토리 항목으로 돌아갑니다.

## 색감과 레이아웃

화이트·차콜을 기본으로 하고 날짜·선택 상태에만 블루 포인트를 사용합니다. 사진이 주인공이 되도록 장식과 그림자를 줄이고, 고딕체와 짧은 전환을 사용합니다. 디자인 기준과 참고 자료는 `docs/design-direction.md`에 정리했습니다. 본문은 작은 콘텐츠 단위로 처음 화면에 들어올 때만 320ms 동안 나타나며, 참석 응답과 계좌는 260ms 동안 펼치고 접습니다. 모션 감소 설정에서는 전환 없이 즉시 표시합니다. 애니메이션을 지원하지 않는 브라우저는 기본 접기·펼치기를 사용합니다. 등장 효과를 위해 본문을 미리 숨기지 않으므로 효과가 실행되지 않아도 읽을 수 있습니다.


본문 문구와 콘텐츠 블록은 가운데 정렬하고, 계좌 복사 버튼과 우측 바로가기처럼 기능상 필요한 조작 요소는 해당 위치를 유지합니다. 캘린더 아래 예식 날짜는 읽기 쉬운 크기로 표시합니다.

## 카카오톡 링크 미리보기

배포된 청첩장 URL을 카카오톡에 보내면 HTML의 `og:title`, `og:description`, `og:image`를 사용합니다. 공유 이미지는 `assets/share/kakao-thumbnail.jpg`이며 공개 GitHub 저장소의 절대 URL로 지정했습니다. 공개 배포 주소가 생긴 뒤 [카카오톡 URL 메타정보 관리](https://developers.kakao.com/tool)에서 미리보기를 확인하세요. 이전 미리보기가 계속 보이면 해당 URL의 캐시를 초기화해야 합니다. `file://` 주소에서는 미리보기를 확인할 수 없습니다.

## 배포

운영에는 서버가 필요하지 않습니다. 배포 전 `npm run build`를 실행해 **`dist/`** 전체를 정적 호스팅에 올리세요. 빌드는 변경된 CSS·JS에 내용 해시가 들어간 파일명을 부여하고 원본 JPG를 제외합니다. `npm run images`는 사진을 바꿀 때만 개발 환경에서 실행합니다. 모든 경로는 상대 경로입니다.

## 확인할 화면

- 작은 모바일 화면에서 가로 스크롤이 없는지
- PC와 모바일에서 우측 바로가기 버튼으로 12개 구역에 이동하는지
- 사진을 넣은 뒤 첫 사진이 표시되는지, 로딩 중 건너뛰기와 재생 중 일시정지가 동작하는지
- 캘린더·D-DAY가 `eventDate`와 일치하는지, 지도·공유·복사 버튼이 동작하는지


## 캘린더 기기 진단

`?calendarDebug=1#calendar`로 접속하면 캘린더 선택창에 ‘캘린더 진단 로그’가 표시됩니다. 일반 방문에는 로깅 리스너·저장·전송 UI가 활성화되지 않습니다. 테스트 모드는 기기/브라우저 UA, 화면 크기, 코드 버전, 클릭 종류, 팝업 및 대체 경로, 페이지 포커스·가시성 변화와 시각만 기록합니다. 임의 오류 메시지·URL/쿼리·입력 내용·계좌·쿠키는 수집하지 않습니다. 청첩장 공유 URL에서는 테스트 쿼리를 제거합니다.

최근 60개 이벤트를 해당 탭의 sessionStorage에 보관해 앱에서 돌아오거나 대체 경로가 재로딩되어도 이어서 볼 수 있습니다. 저장소가 차단되면 현재 페이지의 메모리에서만 동작합니다. ‘새 테스트 시작’은 이 진단 기록만 초기화합니다. GitHub 자동 업로드는 없으며 토큰도 사용하지 않습니다. ‘GitHub에 로그 보내기’는 최근 기록을 채운 공개 이슈 작성창을 열고, 사용자가 로그인 후 등록해야 전송됩니다. 링크 길이에 맞춰 오래된 기록이 제외되면 omitted에 개수를 기록합니다. 이슈 등록 후 해당 URL을 전달하면 로그를 분석할 수 있습니다.

`visibility=hidden`이나 포커스 이동은 외부 앱/다른 탭/알림창 등의 징후일 뿐, 앱 실행·일정 저장 성공을 증명하지 않습니다. 브라우저 로그로 삼성 캘린더 내부의 거절 사유까지 확인할 수는 없습니다. 정확한 앱 지원 여부가 필요하면 기기 ADB 진단을 병행합니다.
