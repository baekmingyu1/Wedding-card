# 모바일 청첩장

서버 없이 동작하는 정적 청첩장입니다. `index.html`을 브라우저에서 열어 미리 볼 수 있습니다.

## 내용과 사진 바꾸기

`content.js`에서 이름, 부모님 성함, 예식 정보, 초대글, 참석 응답 링크, 교통 안내, 계좌 정보를 수정합니다. 신랑·신부 소개에는 전달받은 부모님 성함과 ‘아들·딸’ 관계를 표시합니다. 참석 응답 링크와 신부 측 계좌 정보는 아직 확정되지 않아 준비 문구로 표시하거나 링크를 숨깁니다.

본문은 **인트로 → 초대 멘트 → 캘린더 → D-DAY → 갤러리 → 참석 의사 전달 → 신랑 신부 소개 → 마음 전하실 곳 → Location → 오시는 방법 → 화환 사양 안내 → 청첩장 전달하기** 순서입니다. 별도 index 화면과 섹션별 제목·순서 표시는 없습니다. 신랑·신부 소개는 부모님 성함과 ‘아들/딸 이름’을 각각 두 줄로 표시합니다. 캘린더와 D-DAY는 `eventDate`를 기준으로 표시됩니다. 참석 응답은 `rsvpUrl`에 실제 응답 페이지의 HTTPS 주소를 넣으면 활성화됩니다. 네이버·카카오·구글 지도는 아르베 장소 공유·상세 링크로 연결됩니다. 지도 링크는 `naverMapUrl`, `kakaoMapUrl`, `googleMapUrl`에서 관리합니다.

네이버 정적 지도 이미지를 표시하려면 네이버 클라우드 Maps에서 **Static Map**을 선택해 Application을 등록하고, 실제 배포 주소를 **Web 서비스 URL**에 등록하세요. **API Gateway API Key ID**는 `content.js`의 `naverStaticMapKeyId`에 입력하며, 배포 파일과 지도 이미지 요청 URL에서 방문자에게 보입니다. Secret Key는 공개 파일에 넣지 마세요. 등록한 주소에서 이미지 인증이 실패하면 지도 이미지 영역은 숨기고 지도 바로가기 버튼만 표시합니다. `file://`로 직접 열 때는 HTTP Referer 인증을 사용할 수 없어 이미지가 표시되지 않으므로, 등록된 웹 주소에서 확인하세요. 지도 중심은 `naverStaticMapCenter`에 기록한 예식장 주소의 건물 좌표입니다.

달력 아래 **내 일정에 저장**에서 Google 캘린더 편집 화면을 열거나 `.ics` 일정 파일을 내려받을 수 있습니다. 실제 저장은 사용자가 캘린더에서 확인합니다. `eventDate`의 시간대가 포함된 시작 시각을 사용하며, 현재 예식은 `Asia/Seoul` 기준입니다. 종료 시각은 미확정이므로 Google 링크는 시작과 끝이 같은 시작 알림으로, 일정 파일은 종료 시각 없이 생성합니다. 캘린더 앱이 기본 종료 시각을 채울 수 있습니다. 화면에는 설명 문단 없이 저장 방식 버튼만 표시합니다. 내려받은 파일은 호환 캘린더에서 열어야 하며, 모바일 브라우저나 앱에 따라 지원이 다릅니다. 자동 저장·캘린더 구독·로그인 권한 요청은 하지 않습니다. 저장한 일정은 청첩장 변경과 자동 동기화되지 않습니다.

청첩장 전달하기는 기기의 공유 기능을 사용하고, 지원하지 않으면 주소를 복사합니다. 주소 복사 버튼은 언제든 사용할 수 있습니다. 화환 안내 문구는 `wreathMessage`에서 수정합니다.

오프닝은 `assets/opening/DSC*.jpg`의 파일명 순서대로 만든 **15장**을 사용합니다. 첫 방문에는 사진 15장을 준비하는 동안 진행률이 있는 로딩 화면을 보여 주고, 모두 화면 표시 준비를 마친 뒤 자동 재생합니다. 로딩 중에도 화면 아래의 **청첩장 바로 보기** 링크나 키보드의 본문 건너뛰기 링크로 바로 이동할 수 있습니다. 사진 요청은 최대 3개씩 진행하며, 건너뛰면 남은 오프닝 요청을 새로 시작하지 않습니다. 사진 전환 중에는 이전 장면을 유지하고 새 장면을 부드럽게 겹쳐 보여줍니다.

로딩·자동 재생·일시정지 중에는 본문 스크롤과 포커스 이동을 잠급니다. 초대글 바로 보기나 키보드의 본문 건너뛰기로 즉시 잠금을 풀 수 있으며, 정상 재생 완료 시에도 본문으로 이동합니다. 재생 중에는 일시정지하거나 건너뛸 수 있습니다. 모션 감소 설정을 켠 브라우저는 자동 재생 없이 한 화면의 사진을 보여주고 스크롤을 잠그지 않습니다. 재생 중 모션 감소 설정을 켜도 잠금이 해제됩니다. 깊은 링크나 스크롤 위치를 복원한 경우에는 기존 스크롤 방식으로 이동할 수 있습니다.

우측 목차의 `오프닝` 또는 맨 아래 `처음부터 다시 보기`를 누르면 첫 사진과 제목으로 돌아가 오프닝이 다시 시작됩니다. 본문에서 직접 맨 위로 스크롤해도 처음부터 재생됩니다.

모바일과 세로 태블릿에서도 사진이 배경처럼 화면을 채우고 문구가 그 위에 나타납니다. 가로 사진의 전체 장면을 유지하기 위해 화면 주변은 같은 사진을 흐리게 확장하며, 모든 장면은 같은 위치에 고정됩니다.

원본 JPG는 `assets/opening/`에 보관하고 Git에서는 제외합니다. 웹용 사진은 480·768·1024·1600px WebP와 96px의 흐린 배경 이미지로 만들어집니다. 흐린 배경은 작은 데이터 이미지로 목록에 포함되어 사진 전환 전에 준비됩니다. 모바일은 최대 1024px 후보를 선택하며, PC는 화면 크기와 DPR에 맞게 최대 1600px 후보를 선택합니다. 각 파일명에 내용 해시가 들어가므로 사진을 다시 만들면 URL도 바뀝니다.

사진을 교체한 뒤에는 `npm install`과 `npm run images`를 실행하세요. 이 명령은 `opening-images.js`와 `index.html`의 첫 사진 preload를 함께 갱신합니다. `assets/opening/frames/`의 생성 파일과 변경된 HTML·JS를 한 번에 배포해야 합니다. 이전 파일은 캐시된 페이지를 위해 자동 삭제하지 않습니다. 이미지가 실패하면 자리 표시 화면을 사용하며 재생은 계속됩니다.

갤러리 원본 45장은 `assets/gallery/`에 보관합니다. `npm run gallery:images`를 실행하면 640·1200px WebP와 `gallery-images.js`가 만들어집니다. 원본 JPG는 Git·배포에서 제외하며, 한 페이지에 8장씩 보여줍니다. 사진을 추가·교체한 뒤 생성 명령을 다시 실행하세요. 사진 팝업에서는 핀치·더블 탭 확대를 제한하며, 본문에서는 브라우저 확대를 사용할 수 있습니다. 팝업을 연 뒤 브라우저 뒤로가기를 누르면 팝업부터 닫히며, 앞으로가기로 마지막으로 본 사진을 다시 열 수 있습니다. 닫기 버튼·팝업 바깥 여백·Escape로 닫아도 같은 히스토리 항목으로 돌아갑니다.

## 색감과 레이아웃

본문 문구와 콘텐츠 블록은 가운데 정렬하고, 계좌 복사 버튼과 우측 바로가기처럼 기능상 필요한 조작 요소는 해당 위치를 유지합니다. 캘린더 아래 예식 날짜는 읽기 쉬운 크기로 표시합니다.

## 카카오톡 링크 미리보기

배포된 청첩장 URL을 카카오톡에 보내면 HTML의 `og:title`, `og:description`, `og:image`를 사용합니다. 공유 이미지는 `assets/share/kakao-thumbnail.jpg`이며 공개 GitHub 저장소의 절대 URL로 지정했습니다. 공개 배포 주소가 생긴 뒤 [카카오톡 URL 메타정보 관리](https://developers.kakao.com/tool)에서 미리보기를 확인하세요. 이전 미리보기가 계속 보이면 해당 URL의 캐시를 초기화해야 합니다. `file://` 주소에서는 미리보기를 확인할 수 없습니다.

## 배포

운영에는 서버가 필요하지 않습니다. 배포 전 `npm run build`를 실행해 **`dist/`** 전체를 정적 호스팅에 올리세요. 빌드는 변경된 CSS·JS에 내용 해시가 들어간 파일명을 부여하고 원본 JPG를 제외합니다. `npm run images`는 사진을 바꿀 때만 개발 환경에서 실행합니다. 모든 경로는 상대 경로입니다.

## 확인할 화면

- 작은 모바일 화면에서 가로 스크롤이 없는지
- PC와 모바일에서 우측 바로가기 버튼으로 12개 구역에 이동하는지
- 사진을 넣은 뒤 첫 사진이 표시되는지, 로딩 중 건너뛰기와 재생 중 일시정지가 동작하는지
- 캘린더·D-DAY가 `eventDate`와 일치하는지, 지도·공유·복사 버튼이 동작하는지
